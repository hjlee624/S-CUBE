# S-CUBE — 요구사항

## 1. 사용자 시나리오

### S1. 표준횡단면 기반 토공 수량산출 (반자동 — 클릭·판단만)
> **1순위 경로**: 도면 치수를 눈으로 읽어 수기 입력하지 않는다. 사람은 **원지반선과
> 계획선 어디를 클릭할지 판단**만 하고, 절토/성토 단면적은 도구가 좌표에서 산정한다.

1. 도면(DXF/DWG) 로드 → 축척 캘리브레이션(기준 치수 2점 클릭, 실제값 입력)
2. 횡단면도에서 **원지반선 클릭** → **계획선 클릭** (2클릭) → 두 프로파일 사이가
   자동 폐구간으로 구성되어 **절토·성토 단면적이 각각 자동 산정** (FR-3.10)
3. 산정된 절토/성토 단면적이 **활성 측점**의 해당 항목에 **자동 기입**
   (측점은 도면 제목 TEXT 자동 인식, 실패 시 **번호만 입력**으로 폴백 — FR-4.2)
4. 다음 측점 반복 (또는 객체 기반 후보 그룹핑으로 일괄 — Phase 5)
5. 측점 간 연장 자동 계산 → 양단면평균법으로 구간 체적 산출
6. 규격 입력(예: 유용토, 사토) → 수량산출서 출력

> **대체 경로(강등)**: 절토/성토가 이미 **폐합 폴리라인**으로 그려져 있으면 그 폴리라인을
> 1클릭해 면적을 취득한다(FR-3.1). 실무 도면 다수는 열린 선분 조합이라 2클릭 프로파일
> 경로가 기본이며, 폐합 폴리라인 클릭은 보조 경로다.

### S2. 구조물 단면 × 연장
1. 옹벽 표준도에서 콘크리트 단면 폴리라인 클릭 → 단면적
2. 평면도에서 옹벽 연장 라인 클릭 → 연장
3. 규격 입력(예: 콘크리트 25-24-15) → 체적, 거푸집 면적 산출

### S3. 검증 재산출
1. 기존 .scube 프로젝트 열기
2. 특정 항목 클릭 → 도면상 원본 객체가 하이라이트됨
3. 값 수정 시 하위 산출 자동 재계산 및 변경 이력 기록

### FR-3. 측정
| ID | 요구사항 | 우선순위 |
|---|---|---|
| FR-3.1 | 폐합 LWPOLYLINE/POLYLINE 클릭 → 면적 (shoelace) | 필수 |
| FR-3.2 | bulge(원호) 세그먼트 면적 보정 | 필수 |
| FR-3.3 | HATCH 경계 클릭 → 면적 | 필수 |
| FR-3.4 | 내부 구멍(island) 차감 | 필수 |
| FR-3.5 | LINE/POLYLINE 클릭 → 연장 | 필수 |
| FR-3.6 | DIMENSION 클릭 → 실측 좌표 거리 + override 텍스트 병기 경고 | 필수 |
| FR-3.7 | 다중 선택 합산 | 필수 |
| FR-3.8 | 열린 선분 자동 폐합 탐색 (tolerance snap + 그래프 순환) | 권장(Ph.5) |
| FR-3.9 | 측정 결과에 원본 엔티티 handle 저장(역추적) | 필수 |
| FR-3.10 | **원지반선 클릭 + 계획선 클릭(2클릭) → 절토/성토 단면적 자동 산정** | 필수 |

**FR-3.10 상세 (반자동 핵심 워크플로):**
1. 원지반선(자연지반) 폴리라인/선분 클릭 + 계획선(설계면) 폴리라인/선분 클릭 (2클릭)
2. 두 프로파일의 **공통 x구간**에서 사이 폐구간을 자동 구성
3. 교차점(breakpoint)을 기준으로 **부호 분리**: 계획선이 원지반보다 **아래 = 절토**,
   **위 = 성토** → 절토/성토 단면적을 **각각** 산정
4. 산정 결과를 **활성 측점**의 절토/성토 항목에 자동 기입 (measurement.method =
   `profile-cut-fill`, 역추적을 위해 두 프로파일 handle을 sourceHandles에 보존)
5. 경고: 공통 x구간 없음 / 프로파일이 비단일값(non-monotonic x) → UI 노출
> 이 워크플로는 P5-1~3의 '임의 클릭점 최소폐합 face 탐색'과는 **별개 알고리즘**
> (두 프로파일의 차집합 적분)이다.

### FR-4. 수량 산출
| ID | 요구사항 | 우선순위 |
|---|---|---|
| FR-4.1 | 단면적 × 연장 = 체적 | 필수 |
| FR-4.2 | 측점 관리 — **측점 번호만으로도 생성 가능**, 상세표기(No.x+xxx.xxx)는 선택 | 필수 |
| FR-4.3 | 양단면평균법 구간 체적 V = (A1+A2)/2 × L | 필수 |
| FR-4.4 | 측점 불연속(전/후) 처리 — 동일 측점 2개 단면 | 필수 |
| FR-4.5 | 절토·성토 등 다중 항목 동시 관리 | 필수 |
| FR-4.6 | 각주법(원뿔대) 선택 옵션 | 선택 |
| FR-4.7 | 수동 입력 항목(도면 외 수량) 추가 — **수기 입력은 여기로 한정** | 필수 |
| FR-4.8 | **계산유형 분류에 따른 자동 수량식 생성** (BOQ 기반, 최소 8종) | 필수 |
| FR-4.9 | **파생 수량 반자동 취득** — 콘크리트 단면 선택 시 거푸집(접촉면)·비계(외주×높이)·동바리(면적×높이)가 각 계산유형으로 자동 전개 | 필수 |

**FR-4.8 계산유형(CalcType) 8종** — 03-DATA-MODEL·[quantity 문서](../docs/quantity-calc-taxonomy.md)와 1:1:
`section-length`(단면×연장)·`area-thickness`(면적×두께)·`area`(직접면적)·
`contact-length`(접촉둘레×연장, 파생)·`length`(연장)·`count`(개수)·`ref`(항목참조)·
`manual`(수동). 각 유형은 유형에 맞는 `FormulaNode` 트리를 자동 생성한다.

**FR-4.9 파생 수량**: 사람은 **높이/타설고 1개 정도만** 판단·입력하고, 거푸집 접촉변·
구조물 외곽둘레·바닥 수평면적은 도면 기하에서 자동 취득한다. 파생항목은 원본 콘크리트
항목의 handle을 `sourceRefs`로 물어 역추적을 유지한다(계수 직접입력 금지가 원칙).

## 3. 비기능 요구사항

| ID | 항목 | 기준 |
|---|---|---|
| NFR-1 | 렌더 성능 | 10만 엔티티 도면 초기 렌더 3초 이내, 팬/줌 30fps 이상 |
| NFR-2 | 파싱 성능 | 50MB DXF 파싱 10초 이내 (Web Worker, UI 블로킹 없음) |
| NFR-3 | 정확도 | 면적 계산 오차 1e-9 상대오차 이내 |
| NFR-4 | 보안 | 도면 파일 외부 전송 없음. 로컬 서버는 127.0.0.1 바인딩 |
| NFR-5 | 오프라인 | 인터넷 연결 없이 전 기능 동작 |
| NFR-6 | 브라우저 | Chrome/Edge 최신 2개 버전 |
| NFR-7 | 언어 | UI 한국어. 코드/주석 영문, 도메인 용어는 한국어 병기 |
| NFR-8 | **자동화율** | 도면 유래 수치의 **수기입력 비율 0% 목표**. 수기입력은 도면 외 수량(FR-4.7)으로 한정 |
| NFR-9 | **조작 효율** | 대표 워크플로별 **클릭 수 상한** 정의·회귀 감시(예: 표준횡단 1측점 절토/성토 ≤4클릭) |

> NFR-8·9는 Phase 6 E2E 계측 훅(클릭/타이핑 카운트)으로 검증한다(P6-6·P6-7).
> 이 지표가 없으면 "값 손입력 창"을 만들어도 PLAN 위반이 아니게 되어 반자동 의도가
> 검증 불가해지므로 **1급 성공기준**으로 명문화한다.

## 4. 제약 조건

- Node.js **24 LTS 이상** (개발 PC 확인: v24.18.1)
- Vite **8.0 이상** (Rolldown 번들러 기본 내장)
- Biome (ESLint/Prettier 미사용)
- 패키지 매니저: **pnpm** (workspace 사용)
- 원본 DWG는 읽기 전용, 절대 덮어쓰지 않음
