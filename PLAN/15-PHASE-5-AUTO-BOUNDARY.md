# Phase 5 — 자동 폐합 탐색 · 레이어 규칙 · DWG 직접 입력

**목표**: 클릭 횟수를 대폭 줄인다. 실무 도면(열린 선분 조합)에서도 클릭 한 번에 면적이 나온다.

> Phase 4까지가 "된다"의 영역이라면, Phase 5는 "쓸 만하다"의 영역이다.
> **전체 공수의 절반이 여기에 몰려 있다.**

## 작업 항목

### 5-A. 자동 폐합 영역 탐색 (핵심 난제)
CAD의 `BOUNDARY`/`BPOLY` 명령이 하는 일을 직접 구현한다.

- [ ] **P5-1** 선분 그래프 구축
  - 모든 LINE/ARC/POLYLINE 세그먼트를 간선으로, 끝점을 정점으로
  - **tolerance snap**: 끝점 간 거리 < ε 이면 동일 정점으로 병합
    (ε 은 도면 단위 기준 자동 추정 + 사용자 조정 가능)
- [ ] **P5-2** 교차점 분할 — 선분이 교차하면 교점에서 분할하여 정점 추가
- [ ] **P5-3** 클릭점 포함 최소 폐합 영역 탐색
  - 평면 그래프의 face 탐색 (각도 정렬 기반 next-halfedge 순회)
  - 또는 클릭점에서 ray casting으로 후보 축소 후 순환 탐색
- [ ] **P5-4** 성능 — 대형 도면에서 클릭 후 응답 500ms 이내
  (뷰포트 내 엔티티로 후보 제한, 결과 캐시)
- [ ] **P5-5** 실패 시 우아한 폴백 — 찾은 경로를 하이라이트하고
  "여기서 끊겼습니다" 지점을 표시, 사용자가 수동 연결
- [ ] **P5-6** tolerance 조정 슬라이더 — 실시간 미리보기

### 5-B. 객체 기반 일괄 산출 (레이어 비의존이 1순위)
> **분류·일괄화는 객체(엔티티)의 관측 가능 속성**(기하·색상·선형·배치 근접성) 기반을
> 1순위로 한다. 레이어 규칙은 **있으면 활용하는 보조 가속 수단**으로 강등 (00-OVERVIEW
> 원칙 3, R-9). 실무 도면은 레이어 규칙이 없을 확률이 높다는 전제.

- [ ] **P5-7c** **기하/색상/선형 기반 후보 자동 그룹핑 → 사용자 승인** (신규 필수)
  - 동일 형상/색/선형 유사도로 엔티티 군집화 → 항목 후보 제시(자동 확정 금지)
- [ ] **P5-7d** **레이어 비의존 클릭 절감** (신규 필수)
  - 다수 횡단면의 제목 TEXT·프레임 인식 → 측점별 원지반/계획선 쌍 **일괄 후보** 제시
    (P3-5·P5-15와 연계) → FR-3.10 2클릭을 다수 단면에 일괄 적용
- [ ] **P5-7** 레이어 → 항목 매핑 규칙 정의 UI — **옵션으로 강등**
  (예: `CUT-AREA` 레이어의 모든 폐합 영역 → '절토' 항목). 규칙이 있는 도면에서만 가속
- [ ] **P5-8** 규칙 저장/재사용 (프로젝트 간 이식)
- [ ] **P5-9** 일괄 실행 + 결과 미리보기 → 사용자 승인 후 반영 (객체/레이어 공통)
- [ ] **P5-10** 사내 CAD 작도 표준(레이어 명명 규칙) 문서화 및 권고안 작성 — 보조
  - 표준이 있으면 레이어 규칙 가속을 쓸 수 있으나, **없어도 객체 기반 경로가 기본 동작**한다

### 5-E. 블록/심볼 자동 카운트 (count 유형 — 신규)
- [ ] **P5-17** 동일 `blockName` INSERT 인스턴스를 블록명(·레이어)으로 집계해 후보 제시
  (사용자 확인식), 선택영역 내 개수 자동 합산
- [ ] **P5-18** 개소당 길이·회당수량(`conversions`) 연동, `count` 항목 `sourceRefs`에
  카운트된 인스턴스 handle 목록 보존(역추적) — 배수·앵커·다웰 등 전량 수동 탈피
  - 검증기준: **자동 카운트 = 수동 카운트 일치**

### 5-C. DWG 직접 입력
- [ ] **P5-11** ODA File Converter 설치 감지
- [ ] **P5-12** DWG 드롭 → 임시 폴더에서 DXF 변환 → 로드 (원본 무손상)
- [ ] **P5-13** 미설치 시 다운로드 안내 및 수동 변환 가이드
- [ ] **P5-14** 변환 실패 로그 및 버전 호환성 안내

### 5-D. 측점 자동 인식 (도전 과제)
- [ ] **P5-15** 횡단면도 배치 패턴 인식 — 제목 TEXT 근접도 기반 단면-측점 자동 연결
- [ ] **P5-16** 인식 결과는 항상 사용자 확인을 거친다 (자동 확정 금지)

## 검증 기준
- 열린 선분으로 그려진 실도면 횡단면 20개 중 **17개 이상**에서 클릭 한 번에 면적 산출
- 자동 폐합 면적 = 수동 폐합 면적 (오차 1e-6)
- 실패 케이스에서 원인 지점이 정확히 표시됨
- **객체 기반** 일괄 산출 후 수동 검토 시간이 개별 클릭 대비 1/3 이하
- **N개 단면 일괄 취득** 시 개별클릭 대비 시간 단축·오검출률 계측(레이어 없이도 동작)
- 블록/심볼 자동 카운트 = 수동 카운트 일치

## 리스크 · 착수 순서
- P5-3(평면 그래프 face 탐색)은 기하 알고리즘 난이도가 높고 엣지 케이스가 많다.
  → **Phase 5 착수 전에 `docs/experiments/` 에서 face 탐색 vs flood-fill 프로토타입을
    먼저 만들어 타당성 검증 후 착수** (로드맵 재확인).
  → 실패 시 대안: 클릭점에서 픽셀 flood-fill로 영역 추정 후 경계 추적 (정확도는 낮지만 견고)
- **우선순위**: 최소 **P5-1(tolerance snap 선분그래프) + P5-3(클릭점 포함 최소 폐합
  face)** 을 우선 구현해 `entity-chain`/`auto-boundary` measurement를 실제 생성.
  레이어 규칙(P5-7~10)은 R-9로 **후순위** 유지.
- **section-area(FR-3.10)·HATCH 파서·자동 폐합**이 열린 선분 산정을 커버하면 사용자
  의도 대부분이 충족된다 → 이 세 가지가 P5-1~6보다 즉효라 **우선순위 상위**.
